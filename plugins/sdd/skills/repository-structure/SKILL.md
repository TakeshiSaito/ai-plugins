# リポジトリ構造定義書作成スキル

アーキテクチャ設計書のレイヤー構成を、実際のディレクトリとファイルの置き方に落とす。新しいファイルをどこに置き、どう名付けるかを、この定義書だけで決められるようにする。

- 出力先: `.sdd/repository-structure.md`
- テンプレート: ./template.md。当てはまらない節は削除する。
- 書き方の例と既定の構成、チェックリスト: ./guide.md
- 既存のリポジトリ構造定義書があれば、その構造と内容を保ったまま更新する。
- レイヤーの分け方、レイヤーと置き場所の対応、モジュールの依存ルール、テストの種類と置き場所はアーキテクチャ設計書で扱う。この定義書では書き写さずに参照する。
- この定義書にはプロジェクト全体の置き方を書く。作業ごとに足すファイルは、ステアリングファイルに書く。

## 決めごと

### ディレクトリ構成

- ツリーには、ディレクトリと、役割の決まったファイル（入口、設定、DI コンテナなど）だけを書く。機能ごとに増えるファイルは `{機能}.py` のように書き、1つずつは並べない。
- まだ使わないディレクトリは作らない。必要になってから足す。

### ディレクトリの役割

- ディレクトリごとに、置くもの、置かないもの、対応するレイヤーを書く。
- 「置かないもの」には、置き間違えやすいもの（例: 入口のモジュールにデータアクセスの処理を書く）を書く。

### 命名規則

- ファイル、ディレクトリ、テストファイルの名前の付け方を、例と一緒に書く。
- 言語やツールの慣習（例: Python なら小文字のスネークケース）に従う。

### 新しいファイルの置き場所

- よく足すもの（機能、入口、外部サービスの実装、テストなど）ごとに、置き場所と、あわせて更新するもの（依存ルールのチェックツールの設定、DI コンテナなど）を表にする。

### git に入れないもの

- 生成物、仮想環境、データやログ、秘密情報（`.env` など）を書き、`.gitignore` と合わせる。

## 作成後にすること

- ツリーと実際のリポジトリ（`git ls-files`）が食い違っていないか確かめる。
- ツリーとアーキテクチャ設計書のレイヤー構成、モジュール依存表、依存ルールのチェックツールの設定が食い違っていないか確かめる。
- 「git に入れないもの」と `.gitignore` が合っているか確かめる。
