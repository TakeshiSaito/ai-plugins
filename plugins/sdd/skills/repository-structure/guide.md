# リポジトリ構造定義ガイド

## 基本原則

### 1. 置き場所を迷わない書き方にする

**悪い例**:
```
src/app/
├── utils/      # 便利な関数
└── common/     # 共通の処理
```

**良い例**:
```
src/app/
├── projects.py   # コア: プロジェクトの作成・取得と、保存先の抽象
└── sqlite/       # 出口のアダプター: 保存先の抽象の SQLite 実装
```

`utils` や `common` のように何でも入る名前にせず、レイヤーと責務が名前から分かるようにする。

### 2. 置かないものも書く

**悪い例**:
```
| `src/app/sqlite/` | SQLite の処理 |
```

**良い例**:
```
| `src/app/sqlite/` | 出口のアダプター | 保存先の抽象の SQLite 実装 | 機能の処理、入力の検証 |
```

### 3. アーキテクチャ設計書と二重に書かない

レイヤーの分け方、依存ルール、テストの種類はアーキテクチャ設計書に書き、この定義書からは参照する。
同じことを2か所に書くと、片方だけ更新されて食い違う。

### 4. 今あるものだけを書く

使う予定のディレクトリは作らず、ツリーにも書かない（YAGNI）。
足すときに、定義書とツリーを一緒に更新する。

## 既定の構成

特に理由がなければ、次を使う（Python、uv の場合）。

```
{リポジトリ}/
├── pyproject.toml
├── uv.lock
├── tach.toml
├── test.sh
├── CHANGELOG.md
├── .sdd/
├── src/
│   └── {package}/
└── tests/
```

| 対象 | 規則 | 例 |
|------|------|----|
| モジュール、ディレクトリ | 小文字のスネークケース | `task_lists.py` |
| テストファイル | `test_<モジュール>.py` | `test_task_lists.py` |

git に入れないもの: `.venv/`、`__pycache__/`、`.pytest_cache/`、`.coverage`、`.env`、データとログの置き場所。

## チェックリスト

- [ ] ツリーが実際のリポジトリと一致している
- [ ] ツリーが、アーキテクチャ設計書のレイヤー構成と依存ルールのチェックツールの設定と一致している
- [ ] ディレクトリごとに、置くものと置かないものが書かれている
- [ ] `utils` や `common` のように、何でも入る名前のディレクトリがない
- [ ] よく足すものごとに、置き場所とあわせて更新するものが書かれている
- [ ] 「git に入れないもの」と `.gitignore` が合っている
- [ ] レイヤーの分け方、依存ルール、テストの種類を書き写していない（アーキテクチャ設計書で扱う）
