# 用語集作成スキル

永続ドキュメント（PRD、機能設計書、アーキテクチャ設計書、リポジトリ構造定義書）から用語を拾い、1つの意味に1つの言い方とコード上の名前を決める。

- 出力先: `.sdd/glossary.md`
- テンプレート: ./template.md。当てはまらない節は削除する。
- 書き方の例とチェックリスト: ./guide.md
- 既存の用語集があれば、その構造と内容を保ったまま更新する。
- 用語の言い方と定義は、この用語集で決める。属性、型、制約、例外クラス、入口での扱いは機能設計書で、レイヤーはアーキテクチャ設計書で扱う。この用語集では書き写さずに、その節を参照する。

## 決めごと

### 載せる用語

- プロダクト固有の用語（データ、操作、役割など）と、このプロジェクトで特別な意味で使う言葉（例: 入口、公開 API）だけを載せる。
- 広く知られた技術用語（例: HTTP、SQLite）は載せない。

### 書き方

- 定義は1〜2文で、その用語を知らない人が読んで分かるように書く。定義の中で別の用語を使うなら、その用語も用語集に載せる。
- コード上の名前（クラス名、変数名、テーブル名など）を書き、言い方とコードを1対1にする。
- 同じ意味で使われがちな別の言い方は「使わない言い方」に書く。

### 状態（該当する場合）

- 状態の意味とコード上の値だけを書く。どの状態からどの状態に移れるかは、機能設計書で扱う。

## 作成後にすること

- 永続ドキュメントで「使わない言い方」が使われていたら、用語集の言い方に直す。言い方だけを直し、設計の中身は変えない。
- コード上の名前が、機能設計書のデータ、コンポーネント、例外の名前と一致しているか確かめる。
